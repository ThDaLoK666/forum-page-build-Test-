# แผนสร้างเว็บจริง (ITDS492): ICT Learning Support Forum

สถานะ: แผน รอข้อมูลจากผู้ใช้ ยังไม่ได้แก้โค้ด

## การตัดสินใจที่ยืนยันแล้ว
| เรื่อง | ตัดสินใจ |
|---|---|
| ล็อกอิน | เฉพาะอีเมลมหิดล (@student.mahidol.edu, @mahidol.edu, @mahidol.ac.th) |
| หน้าจอ | รองรับมือถือด้วย (ต้องปรับ layout ที่ออกแบบไว้ 1440px) |
| ข้อมูลตัวอย่างเดิม | ย้ายเป็นข้อมูลเริ่มต้นในฐานข้อมูล ติดป้ายว่าเป็นตัวอย่าง |
| ไฟล์นักศึกษา | แนบกับโพสต์ได้ทันที ขึ้น Pinned Academic Assets เมื่อ TA/อาจารย์ปักหมุด |

## สภาพปัจจุบัน
- ต้นแบบ Next.js 16 + React 19 + Tailwind + shadcn/ui เก็บข้อมูลใน localStorage
- `app/page.tsx` ~1,900 บรรทัด, `app/post/[id]/page.tsx` ~2,300 บรรทัด ผูกกับข้อมูลตัวอย่างในไฟล์
- ยังไม่มี .env และยังไม่มี Supabase client
- Supabase มี 2 โปรเจกต์ (ict-community-project, paokana) สถานะ INACTIVE ทั้งคู่
- ร่าง `schema_draft.sql` ทดสอบกับ Postgres จำลองแล้ว ยังไม่ทดสอบบน Supabase จริง

ช่วง 2 และ 3 สำคัญที่สุด ทำก่อนช่วงอื่น

## ความเสี่ยง
- Supabase ฟรีพักโปรเจกต์เมื่อไม่มีการใช้งาน เว็บอาจล่มตอนสอบ ต้องปลุกก่อนหรือใช้แพ็กเกจเสียเงิน
- อีเมลยืนยันของ Supabase ฟรีส่งได้น้อยต่อชั่วโมง ต้องตั้ง SMTP ของตนเอง
- ค้นหาภาษาไทยอาจไม่แม่น
- ไม่ได้รับประกันไม่มีบัค แต่จะรายงานสิ่งที่ทดสอบแล้ว/ยังไม่ได้ทดสอบ
- ข้อมูลที่ผมทดสอบกับอีเมลจริงไม่ได้ (ไม่มีกล่องจดหมาย) ต้องให้ผู้ใช้ลองสมัครด้วยอีเมลมหิดลจริง

## ข้อมูลที่ต้องการจากผู้ใช้
1. โปรเจกต์ Supabase ที่จะใช้ (ฟื้น ict-community-project, paokana หรือสร้างใหม่) และยืนยันค่าใช้จ่ายถ้ามี
2. Netlify: ชื่อไซต์/URL ปัจจุบัน
3. อีเมล admin / TA / อาจารย์ (กำหนด role) และอีเมลบัญชีทดสอบ
4. รายวิชาจริง (รหัส ชื่อ สี) และแท็กหัวข้อ
5. นโยบาย guideline ของเว็บ (ถ้ายังไม่มี ผมร่างให้ตรวจ)
6. นโยบายตัวตนนิรนาม: ใครเปิดดูตัวตนจริงได้ (ร่าง: admin + ต้องระบุเหตุผล) และเก็บบันทึกนานเท่าไร ควรปรึกษาอาจารย์
7. SMTP สำหรับอีเมลยืนยัน (หรือยอมปิดการยืนยันอีเมล)
8. เส้นตายที่ต้องเสร็จ
