# แผนงานเว็บ Phase 2 (ITDS492): เชื่อม Supabase

> สถานะ: **ร่างเพื่อรีวิว** ยังไม่ได้สร้างโปรเจกต์ Supabase และยังไม่แตะโค้ดเว็บ
> ไฟล์คู่กัน: `supabase/schema_draft.sql` (ทดสอบรันกับ Postgres จำลองแล้ว ดู "ผลทดสอบ" ท้ายเอกสาร)

## 1. เป้าหมาย
เปลี่ยนต้นแบบที่เก็บข้อมูลใน localStorage ให้เป็นระบบจริงที่ **รักษาจุดขายเดิมไว้ครบ**:
1. ถามโดยซ่อนชื่อจากผู้ใช้อื่นได้จริง (ไม่ใช่แค่ซ่อนบนหน้าจอ) แต่ระบบเก็บตัวตนไว้ตรวจสอบ
2. เก็บคำถาม–คำตอบอย่างเป็นระบบ ค้นหาด้วยวิชา/แท็ก/คำค้น แล้วเจอกระทู้เดิมพร้อมไฟล์

ตรงกับแผนใน Proposal (สไลด์ 56): ข้อมูลจริง → ตรวจความเป็นส่วนตัว → ปรับการค้นหา → ทดสอบกับผู้ใช้

## 2. สิ่งที่เปลี่ยนจากต้นแบบ
| ตอนนี้ (ITDS491) | Phase 2 |
|---|---|
| ข้อมูลใน localStorage ของเบราว์เซอร์ ใช้ได้เครื่องเดียว | Supabase Postgres แชร์ข้ามผู้ใช้ |
| จำลอง role ด้วยปุ่มทดสอบ | Supabase Auth (อีเมลมหิดล) + role ในตาราง `profiles` |
| ซ่อนชื่อที่หน้าจอ (ตัวตนอยู่ในข้อมูลก้อนเดียวกัน) | ตัวตนแยกอยู่ schema `private` API เข้าไม่ถึง |
| ตรวจข้อมูลส่วนตัวที่ฝั่ง client (ข้ามได้) | ตรวจซ้ำที่ฝั่ง server ตอนสร้างโพสต์ |
| ค้นหาด้วย filter ในหน้าเว็บ | ค้นหาที่ฐานข้อมูล (full-text + trigram) |
| ไฟล์เป็นแค่ชื่อไฟล์ | ไฟล์จริงใน Supabase Storage |

## 3. โมเดลข้อมูล (สรุป)
ต่อยอดจาก ER Diagram เดิม (Users / Questions / Answers) ที่ใช้ใน Proposal

| กลุ่ม | ตาราง | หมายเหตุ |
|---|---|---|
| ผู้ใช้ | `profiles`, `user_subjects` | role: student / ta / instructor / admin |
| เนื้อหา | `questions`, `answers`, `comments`, `code_blocks`, `files` | `questions` **ไม่มีคอลัมน์ผู้เขียน** |
| จัดหมวด | `subjects`, `tags`, `question_tags` | Course Tag 2 ระดับ: วิชา + หัวข้อ |
| ปฏิสัมพันธ์ | `votes`, `bookmarks`, `notifications` | votes ใช้ตารางเดียวสำหรับคำถาม/คำตอบ/คอมเมนต์ |
| ส่วนตัว (`private`) | `question_authors`, `identity_access_log` | ผู้เขียนจริง + เลข Anonymous + บันทึกการเปิดดูตัวตน |

ที่ **ยังไม่ทำใน Phase 2** (เป็น Future Work ตาม Proposal): Study Session, Verified Badge ระดับขั้นสูง, Report/Moderation, Recommended for You

## 4. ซ่อนชื่อให้ปลอดภัยจริง (ส่วนสำคัญที่สุด)
- ตัวตนผู้ถามอยู่ใน `private.question_authors` ซึ่งไม่ถูกเปิดผ่าน Supabase API
- หน้าเว็บอ่านกระทู้ผ่าน view `question_feed` ซึ่งแสดง `Anonymous Student #N` แทนชื่อเมื่อ `is_anonymous = true`
- สร้างโพสต์ผ่านฟังก์ชัน `create_question()` เท่านั้น (ไม่มี policy ให้ insert ตรง) จึงบังคับใช้กฎได้ที่เดียว
- ไฟล์แนบไม่มีคอลัมน์ผู้อัปโหลด โพสต์นิรนามจึงไม่หลุดผ่านไฟล์
- แอดมินเปิดดูตัวตนได้ด้วย `reveal_author()` ต้องระบุเหตุผลและถูกบันทึกทุกครั้ง (ตอบโจทย์ "เก็บตัวตนไว้ตรวจสอบ")
- ข้อควรระวัง: view นี้ทำงานด้วยสิทธิ์เจ้าของโดยตั้งใจ Supabase advisor อาจเตือน "security definer view" ให้บันทึกว่าเป็นการออกแบบที่ตั้งใจ

## 5. การค้นหา
- `search_questions(q, subject, tags, ...)` รวมวิชา + แท็ก + คำค้นไว้ในฟังก์ชันเดียว
- ใช้ full-text แบบ `simple` + `pg_trgm` (เทียบความคล้าย)
- **ความเสี่ยง:** Postgres ไม่มีตัวตัดคำภาษาไทย คำค้นไทยอาจได้ผลไม่ดี ต้องทดสอบด้วยคำค้นไทยจริงตั้งแต่ต้น ถ้าไม่พอให้พิจารณา extension ที่รองรับภาษาไทย/CJK หรือตัดคำฝั่งแอปก่อนบันทึก

## 7. แผนทดสอบ
**ความเป็นส่วนตัว (ต้องผ่านก่อนเปิดให้ใช้):**
- ผู้ใช้ B เรียก API ตรง ๆ แล้วไม่เห็นผู้เขียนโพสต์นิรนามของ A ในทุกตาราง/ทุก endpoint
- ผู้ใช้ทั่วไปอ่าน `private.*` ไม่ได้ และแก้ `role` ตัวเองไม่ได้
- โพสต์ที่มีอีเมล/เบอร์/รหัสนักศึกษาถูกปฏิเสธที่ server แม้ข้ามการตรวจฝั่ง client
- ผู้ใช้ทั่วไปตั้ง `is_accepted` / `is_verified` เองไม่ได้ (ดูข้อ TODO ใน SQL)

**การใช้งาน:** ทำซ้ำภารกิจ T1 (ค้นเอกสาร) และ T2 (ถามซ่อนชื่อ) ด้วยข้อมูลจริง เทียบกับผล P1 (T1 มัธยฐาน 39 วินาที เป้า 35)

## 8. ผลทดสอบร่าง SQL (รันกับ Postgres จำลอง ไม่ใช่ Supabase จริง)
ผ่านทั้งหมด: สร้าง schema ได้, อีเมลนอกโดเมนมหิดลสมัครไม่ได้, โพสต์ที่มีเบอร์โทรถูกปฏิเสธ, เจ้าของโพสต์เห็น `is_mine = true`, ผู้ใช้อื่นเห็นแค่ `Anonymous Student #N`, อ่าน `private.*` ไม่ได้, ค้นหาด้วยคำค้น/วิชา/แท็กได้, โหวตแล้วคะแนนอัปเดต
**ยังไม่ได้ทดสอบ:** `pg_trgm` จริง (ตัวจำลองไม่มี), Storage, Auth จริง, ค้นหาภาษาไทย, ประสิทธิภาพ

## 9. เรื่องที่ต้องให้คุณตัดสินใจ
1. **โดเมนอีเมลที่อนุญาต:** ตอนนี้ร่างไว้ `@student.mahidol.edu`, `@mahidol.edu`, `@mahidol.ac.th` ตรงกับที่ต้องการไหม และ P2/P3 ที่เป็นคนนอกจะล็อกอินอย่างไร
2. **ไฟล์ที่นักศึกษาอัปโหลด:** ให้ขึ้นใน "Pinned Academic Assets" ทันที (แบบต้นแบบ) หรือรอ TA/อาจารย์ปักหมุดก่อน (แนะนำแบบหลังเพื่อคุมคุณภาพ)
3. **คำตอบนิรนามได้ไหม:** ตอนนี้ให้ซ่อนชื่อได้เฉพาะ "คำถาม" ตามแบบสำรวจและ Proposal
4. **นโยบายตัวตนนิรนาม:** ใครมีสิทธิ์เปิดดูตัวตนจริง (ร่างไว้เฉพาะ admin + ต้องมีเหตุผล) และเก็บบันทึกนานเท่าไร ควรปรึกษาอาจารย์ที่ปรึกษา
5. **ภาษาไทยในการค้นหา:** ยอมรับข้อจำกัดช่วงแรก หรือใช้เวลา M7 เพิ่มเพื่อทำให้ดีขึ้น
