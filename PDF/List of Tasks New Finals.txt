📌 รายการ Goal และ Task ย่อย 
🎯 Goal 1: ค้นหาแนวทางแก้ปัญหาเดิมและคลังไฟล์เรียนถาวรได้ทันที 
ข้อมูลไม่ไหลหาย 
สิ่งที่ระบบช่วยแก้: แก้ปัญหาข้อความรันหายในแชทไลน์ ค้นหากระทู้ที่มีคนเคยตอบไว้อย่างรวดเร็ว 
และโหลดไฟล์เรียนได้ตลอดเวลาโดยไม่มีวันหมดอายุ 
🔍 Task 1.1: ค้นหากระทู้ค าถามเก่าและดาวน์โหลดไฟล์วิชาถาวร (Search Questions & 
Download Assets) 
• เป้าหมายผู้ใช้: ต้องการหาทางแก้ปัญหาจากค าถามเก่า หรือดาวน์โหลดไฟล์วิชาที่ต้องการบนหน้าฟีดรวม 
โดยไม่ต้องกลัวข้อมูลไหลหาย 
• ขั้นตอนการท างานบน UI (Flow แบ่งตามระยะการใช้งาน): 
o     [ก่อนใช้งาน - Pre-usage]: ผู้ใช้เจอบั ๊ กในวิชาเรียนหรือต้องการไฟล์สไลด์/การบ้านกะทันหัน 
ไม่อยากตั้งกระทู้ถามใหม่ให้เสียเวลา และไม่อยากเลื่อนหาในแชทไลน์เพราะไฟล์หมดอายุและข้อความไหลหาย 
o   [ระหว่างใช้งาน - In-usage]: 
▪ สืบค้นปัญหา: พิมพ์คีย์เวิร์ดในแถบค้นหาอัจฉริยะ Keyword Search & Tag Cloud 
ด้านบนสุด หรือคลิกปุ่มแฮชแท็กวิชา/หัวข้อ (เช่น #ITCS210, #Java) บนการ์ดค าถามที่เห็น -> UI 
แสดงรายการค าถามทั้งหมดที่ตรงกับแท็กหรือค าค้นหาขึ้นมาบนฟีดหลัก 
▪ ดาวน์โหลดไฟล์อ้างอิง: มองไปที่กล่องคลังความรู้ปักหมุด Pinned Academic 
Repository ด้านบนสุดของหน้าผลการค้นหา แล้วคลิกปุ่ม [Download] 
บนการ์ดไฟล์ที่แสดงป้าย • No expiry -> UI ด าเนินการดาวน์โหลดไฟล์ประกอบการเรียนลงเครื่อง 
o         [หลังใช้งาน - Post-usage]: ผู้ใช้ได้ไฟล์เรียนถาวรลงเครื่อง หรือเจอกระทู้ค าตอบเก่าที่ตรงกับปัญหาทันที 
น าวิธีแก้ไปใช้งานต่อได้เลยโดยไม่ต้องรอเพื่อนมาตอบ

🎯 Goal 2: ตั้งค าถามซอร์สโค้ดและรูป Error แบบไม่เปิ ดเผยตัวตน 
ป้องกันความอายและข้อมูลไม่สูญหาย 
สิ่งที่ระบบช่วยแก้: ท าลายก าแพงความกลัวในการถามค าถามง่ายๆ จัดฟอร์แมตโค้ดไม่ให้เละ และซ่อนชื่อจริงบนเว็บบอร์ดอย่างปลอดภัย 
📝 Task 2.1: ร่าง ตั้งค าถาม แปะโค้ด และส่งโพสต์นิรนาม (Ask Question & Publish 
Anonymously) 
• เป้าหมายผู้ใช้: ต้องการตั้งค าถามใหม่ แปะโค้ดและรูป Error ตรวจเช็คความปลอดภัย แล้วส่งขึ้นบอร์ดโดยไม่เปิดเผยตัวตนจริง 
• ขั้นตอนการท างานบน UI (Flow แบ่งตามระยะการใช้งาน): 
o     [ก่อนใช้งาน - Pre-usage]: ผู้ใช้ติดบั ๊ กเขียนโค้ดไม่ผ่านช่วงดึก 
อยากถามเพื่อนแต่กลัวค าถามง่ายเกินไปจนโดนมองว่าไม่เก่ง และพิมพ์โค้ดในแชทปกติแล้วบรรทัดเละ อ่านยาก 
o   [ระหว่างใช้งาน - In-usage]: 
▪ เปิ ดหน้าตั้งค าถาม: คลิกปุ่ม [+ New Post] (หรือ Ask Question) 
ที่มุมบนขวาของหน้าจอหลัก -> UI เปิดหน้าต่างร่างค าถามใหม่ที่แบ่งเป็นฝั่งพิมพ์ (ซ้าย) และฝั่งพรีวิว 
Live Preview Sandbox (ขวา) 
▪ พิมพ์อธิบายและติดแท็ก: พิมพ์ชื่อค าถาม รายละเอียด และเลือกแท็กวิชา/หัวข้อ (เช่น #ITCS212, 
#Java) -> UI แสดงแท็กเป็นป้ายก ากับชัดเจน 
▪ วางโค้ดและแนบรูป Error: วางซอร์สโค้ดในกล่อง Dedicated Code Snippet 
Block และแนบรูป Log Error -> UI จัดฟอร์แมตโค้ดแสดงเลขบรรทัด แยกสี Syntax 
และเรนเดอร์ภาพ Error ต่อท้ายแบบ Inline 
▪ สลับโหมดซ่อนตัวตน: คลิกเปิดสวิตช์ Anonymity Masking Toggle (Post as 
Anonymous) -> UI เปลี่ยนสถานะเป็นเปิดใช้งาน 
▪ ตรวจทานและกดส่งโพสต์: มองฝั่ง Live Preview Sandbox ขวามือเพื่อเช็คความเรียบร้อย 
และดูตราสีเขียว ✓ Pre-Publishing Audit: Safe ที่ยืนยันว่าสลับเป็นชื่อนิรนาม 
(เช่น Anonymous Student #12) แล้วจริงๆ จากนั้นคลิกปุ่ม [Publish Post] -> UI 
ปิดหน้าร่างโพสต์ลง 
o         [หลังใช้งาน - Post-usage]: ระบบพาผู้ใช้ไปยังหน้ารายละเอียดค าถามที่เพิ่งสร้างเสร็จทันที 
กระทู้ถูกจัดเก็บบนบอร์ดถาวร (Asynchronous Board Design) ซ่อนชื่อจริงผู้โพสต์ถาวร 
ช่วยให้สบายใจและนั ่ งรอเพื่อนเข้ามาช่วยตอบ

🎯 Goal 3: ร่วมโต้ตอบ ซักถามรายละเอียด ช่วยเพื่อนแก้ปัญหา 
และช่วยกันโหวตคัดกรองเนื้อหา 
สิ่งที่ระบบช่วยแก้: มีพื้นที่ซักถามย่อยเป็นสัดส่วนไม่ให้ปะปนกับค าตอบหลัก และคัดกรองค าตอบที่ดีที่สุดขึ้นมาให้อ่านได้ง่าย 
💬 Task 3.1: ดีบั๊ กร่วมกันในคอมเมนต์ย่อย และส่งค าตอบหลักเพื่อโหวตคะแนน (Interact, Solve 
& Rate Answers) 
• เป้าหมายผู้ใช้: ต้องการช่วยเพื่อนวิเคราะห์โค้ด พิมพ์อธิบายวิธีแก้/ซักถามข้อมูลเพิ่มในช่องคอมเมนต์ 
และช่วยกันโหวตคัดกรองค าตอบที่ดีที่สุด 
• ขั้นตอนการท างานบน UI (Flow แบ่งตามระยะการใช้งาน): 
o     [ก่อนใช้งาน - Pre-usage]: ผู้ใช้เห็นเพื่อนตั้งกระทู้ถามเรื่องที่ตนเองเคยแก้ได้ 
หรือต้องการซักถามข้อมูลโค้ดของเพื่อนเพิ่มเติม แต่ไม่อยากพิมพ์คอมเมนต์ปะปนกันจนมั ่ วและหาแนวทางแก้หลักไม่เจอ 
o   [ระหว่างใช้งาน - In-usage]: 
▪ เข้าสู่หน้ารายละเอียดค าถาม: คลิกเลือกกล่องค าถามบนหน้าแรกเพื่อเปิดอ่านค าถาม โค้ด และรูป Error 
อย่างละเอียด -> UI แสดงหน้ารายละเอียดค าถามเดี่ยว (Question Detail View) 
▪ พิมพ์คอมเมนต์ตอบค าถามหรือซักถาม: พิมพ์ค าอธิบายวิธีแก้ แปะโค้ด หรือพิมพ์ถามเพิ่มในช่อง 
Comment Input Box -> UI แสดงกล่องข้อความคอมเมนต์ขึ้นมา 
(หากเป็นการตอบกลับคอมเมนต์เดิม ระบบจะแสดงเป็นแถบเยื้องขอบซ้าย Clarification 
Nested-Comment Line มีเส้นแนวตั้งเชื่อมโยงชัดเจน) 
▪ โหวตคุณภาพค าตอบ: คลิกปุ่มลูกศรชี้ขึ้น (Upvote) หรือชี้ลง (Downvote) บนแผง Peer 
Rating Interface ด้านซ้ายของกล่องคอมเมนต์ -> UI อัปเดตคะแนนโหวตเรียลไทม์ 
และสลับเอาคอมเมนต์ที่ได้คะแนนโหวตสูงสุดขึ้นมาแสดงผลด้านบนสุดอัตโนมัติ 
o         [หลังใช้งาน - Post-usage]: หน้ากระทู้มีพื้นที่พูดคุยสัดส่วนชัดเจน คอมเมนต์ค าตอบที่เพื่อนๆ 
โหวตว่าถูกต้องที่สุดถูกดันขึ้นมาอยู่อันดับแรก ช่วยให้ผู้ใช้อื่นๆ ที่เข้ามาดูทีหลังเข้าใจวิธีแก้ได้ทันที

🎯 Goal 4 (ส่วนขยายพิเศษ): 
ค้นหาและเข้าร่วมกระทู้นัดติวก่อนสอบได้อย่างรวดเร็ว 
สิ่งที่ระบบช่วยแก้: ช่วยให้นักศึกษารวมกลุ่มหาเพื่อนติว หรือเข้าถึงกระทู้นัดหมายทบทวนบทเรียนช่วงก่อนสอบได้ทันทีในคลิกเดียว 
ไม่ต้องเลื่อนหาในแชทกลุ่มที่ข้อความตกอย่างรวดเร็ว 
🔥 Task 4.1: เปิ ดโหมดตัวกรองช่วงวิกฤตใกล้สอบ (Panic Period Filter) 
• เป้าหมายผู้ใช้: ต้องการหาห้อง/กลุ่มนัดติวหนังสือ หรือส่องดูหัวข้อที่เพื่อนๆ นัดรวมตัวติวก่อนสอบในช่วง 1 สัปดาห์ก่อนสอบ 
• ขั้นตอนการท างานบน UI (Flow แบ่งตามระยะการใช้งาน): 
o     [ก่อนใช้งาน - Pre-usage]: เหลือเวลาอีกเพียง 1 สัปดาห์จะถึงวันสอบ ผู้ใช้รู้สึกยังไม่มั ่ นใจในเนื้อหา 
ต้องการหาเพื่อนติวหรือเข้าร่วมกลุ่มทบทวนบทเรียน แต่แชทกลุ่มหลักมีข้อความคุยเล่นเยอะจนหานัดหมายติวไม่เจอ 
o   [ระหว่างใช้งาน - In-usage]: 
▪ เปิ ดโหมดกรองกระทู้นัดติว: คลิกปุ่มรูปหนังสือ/กลุ่มติว [             Study Session Filter 
Button] (หรือปุ่ม Exam Review Mode) ที่อยู่ใต้แถบค้นหาหลักบนหน้าแรก -> UI 
สลับธีมสีหน้าจอเล็กน้อย และรีเฟรชหน้าฟีดรวมเพื่อดึงเฉพาะกระทู้ที่มีแท็กนัดติว (#ติวก่อนสอบ, 
#StudyGroup) ขึ้นมาแสดงผลด้านบนสุดทันที 
▪ ดูรายละเอียดและกดเข้าร่วม: มองดูการ์ดกระทู้นัดติวที่แสดงเวลา สถานที่/ลิงก์ห้องติว และหัวข้อที่จะติว 
จากนั้นคลิกปุ่ม [Join Session] หรือกดปุ่มบันทึกปฏิทิน -> UI อัปเดตสถานะการเข้าร่วม 
และแสดงการ์ดแจ้งเตือนการนัดหมายบนหน้าจอ 
o         [หลังใช้งาน - Post-usage]: ผู้ใช้เข้าร่วมกลุ่มติวส าเร็จ ได้รับวัน เวลา สถานที่/ลิงก์ห้องติวชัดเจน 
และได้รับการแจ้งเตือนก่อนถึงเวลาติว ช่วยให้เตรียมตัวสอบได้อย่างมั ่ นใจ
